AFFILIATE COMMISSION PROGRAM WORKFLOW
======================================

The Affiliate Program allows promoters to earn recurring commissions on platform service fees generated by users they refer. Every time a referred client or freelancer completes a paid transaction, the affiliate promoter is awarded a percentage of the platform fee.

1. DATABASE SCHEMA
------------------
* affiliate_commissions table:
  - commission_id (SERIAL PRIMARY KEY)
  - affiliate_id (INTEGER REFERENCES users(user_id)): The promoter (affiliate) who will receive the commission.
  - referred_user_id (INTEGER REFERENCES users(user_id)): The user who completed the transaction.
  - transaction_id (INTEGER REFERENCES wallet_transactions(transaction_id)): The transaction that triggered the commission.
  - amount (NUMERIC): The affiliate's reward amount (10% of platform fee).
  - platform_fee (NUMERIC): The total service fee collected by the system on the transaction.
  - status (VARCHAR, check constraint: 'pending', 'approved', 'rejected'): Current state of the commission.
  - created_at / updated_at (TIMESTAMP)

2. LINK TRACKING
----------------
* The affiliate program reuses the unique `referral_code` associated with each user's account.
* Affiliates invite users using the referral link pattern: `https://freelancer.sangvish.com/register?ref=CODE`.
* When a user signs up using this link, they are bound to the affiliate promoter through the `referred_by` foreign key in the `users` table.

3. RECURRING COMMISSION CALCULATION HOOK
----------------------------------------
* Every time a contract payment settles (Stripe or wallet checkout, proposal contract funding, or timecard approval), a platform fee is deducted and logged as `commission_amount` in the `wallet_transactions` table.
* The system invokes the `checkAndEarnAffiliateCommission` hook:
  - Verifies if the transacting user was referred by someone.
  - Fetches the latest transaction of the referred user that has a `commission_amount` > 0 and has not been credited for affiliate commission yet.
  - Calculates the affiliate share as exactly **10%** of the platform fee.
  - Inserts a new row in the `affiliate_commissions` table with a status of 'pending'.

4. USER AFFILIATE PORTAL
------------------------
* Location: User Dashboard -> Affiliate Portal (/dashboard/affiliate)
* Users can view:
  - Unique affiliate tracking link.
  - Stats: Total referred sign-ups, pending commission balance, and approved/paid out balance.
  - Commission Ledger: A real-time log of all generated commissions showing referred transactor details, total platform fees, your 10% share, transaction dates, and statuses.

5. ADMIN COMMISSION AUDITING & APPROVAL
----------------------------------------
* Location: Admin Panel -> Affiliate Payouts (/admin/affiliate)
* The admin panel displays all affiliate commissions retrieved from `GET /api/admin/affiliates/commissions`.
* For each pending commission, the admin reviews:
  - Affiliate promoter details (Name + Email).
  - Referred transactor details and transaction ID.
  - Platform fee and affiliate payout amount.
* Actions:
  - APPROVE: Deducts the commission amount from the system wallet, adds it to the affiliate's wallet, records an 'affiliate_commission' completed transaction, and sets status to 'approved'.
  - REJECT: Updates status to 'rejected' without paying.

6. WALLET BALANCE SECURITY
--------------------------
* Database CHECK Constraint: A CHECK constraint `check_balance_non_negative` enforces that the `balance` field in `wallets` can never be less than 0.00.
* API Guards: In approveAffiliateCommission, the system checks the system wallet balance. If the system balance is less than the commission payout amount, the approval is rejected with a 400 Bad Request error to prevent negative escrow balances.
